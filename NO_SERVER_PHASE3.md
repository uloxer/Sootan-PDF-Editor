# Non-web worker: first migration batch (28 October 2026)

This is a tested development batch, **not a replacement installer**. Installed Sootan 3.2.5, its data and its WebView profile are untouched. The standalone 3.2.6 launcher/package and old-origin library migration remain pending before any upgrade. The existing Windows packaging recipe still builds the legacy server-backed application; only its host compilation was updated to include the new bridge source. Do not present that recipe as the completed no-server distribution.

## Implemented boundary

- `app/pdf-services` is a plain PDFBox/BouncyCastle library. SanitizeController delegates to the extracted identical sanitizer mutations. CreateSignatureBase delegates its detached-CMS primitive to the shared service and retains its existing TSA/hardware behavior.
- `app/worker` is a separate Java application with PDFBox, BouncyCastle and Gson dependencies. It does not depend on common/core, Spring, Jetty or Tomcat. `:worker:verifyNonWebRuntime` rejects those dependencies. It contains no listener or HTTP entry point.
- Each advanced job starts one lazy Java process. Stdin carries one bounded UTF-8 JSON request (64 KiB maximum); stdout emits JSON progress/result/error records. Input/output PDF bytes are not base64-encoded through messages. The worker reads only the host-granted job-relative input; it rejects path escape and links. Options are allowlisted per operation. Credentials and request bodies never enter logs; errors retain only a failure class and a generic user message.
- SootanWorker.cs intercepts exact trusted `https://sootan.local/__sootan_worker/<UUID>/...` resources inside WebView2. These are virtual resources, **not an HTTP server or network listener**. POST input/certificate streams explicit File copies to a host-created UUID directory; copies become read-only. POST run starts Java after assigning a Windows kill-on-close JobObject, then writes the stdin request. DELETE job cancels Java/OCR descendants, closes streams and removes only that job directory. Host navigation/close cancels owned jobs. Java tmpdir and helper TEMP/TMP stay inside the private job.
- The native bootstrap advertises only the explicit implemented modes when the private worker artifact and Java executable exist; OCR additionally needs the explicit private helper executable. Viewing does not launch the PDF worker. Production CDP remains off unless its test environment variable is supplied.
- `runtime/desktopWorker.ts` preserves the Blob transport contract behind requestPdfProcessing and the existing tool/FileContext lifecycle. Offline apiClient calls remain denied. Local English resources avoid a languages API request. Password changes retain client permission checks and worker owner authentication; signature validation has an explicit integrity-only response. No arbitrary filesystem or shell-command bridge is exposed.

## Connected modes and limits

| Worker operation | Connected behavior | Not yet equivalent to every legacy option |
|---|---|---|
| sanitize | Existing PDFBox JavaScript, metadata/XMP, attachments, links and optional font removals | Signed inputs are refused rather than silently invalidated |
| aes-encrypt | AES-256 and permission flags | Other key lengths and preserve-existing/selective security changes pending |
| decrypt | Full removal with owner authentication | Reader-only/selective credential removal pending; rejected explicitly |
| ocr | Private English OCRmyPDF, auto/fpdf2/legacy renderer selection, sidecar, deskew, orientation flag | Unpaper cleanup and Ghostscript image removal were already unbundled; refused. UI orientation setting remains a later UI mapping, while worker golden verifies the flag |
| cert-sign-invisible | Selected PKCS12/PFX, software detached CMS signing | Visible appearances, PEM/JKS, hardware, TSA and server certificate modes pending; unsupported modes rejected |
| signature-integrity | Cryptographic CMS integrity and appended-byte coverage | PKIX trust/revocation/custom anchors/document timestamps pending. Report explicitly sets trust false and explains integrity-only scope |

Shared core viewing/search, annotations, local forms, print/save, tabs and local page operations remain available. No pending controller has been deleted.

## Remaining parity and next batches

`packaging/worker/migration-inventory.json` records 119 literal API mappings: 5 shared page-operation mappings, 6 mode-limited worker mappings, 108 not connected to this worker. This is a source inventory, **not a claim that all 119 worked in installed 3.2.5 or all must be migrated independently**. Families: general28, converters28, misc31, security16, forms9, filters6, pipeline1. Existing local WASM features can replace corresponding API paths without a new worker implementation. Helper-dependent branches need individual availability checks; already unbundled GS/unpaper behavior is not a migration regression. Office conversion has bundled Java implementations as well as optional external branches, so it must not be blanket-classified as unavailable.

Prioritize confirmed installed functionality in serial batches: security option/signature parity; remaining plain PDFBox transformations/inspection and document formatting; native conversion branches; forms/annotations only where the existing local engine lacks parity. Retain source and disabled capability states until each batch is connected and tested. Do not advertise the legacy full tool catalog as implemented by this six-mode worker.

Before any real upgrade, copy the actual Data and WebView profile outside the installer tree and record hashes. Implement/test an explicit one-time old HTTP-origin IndexedDB/library export/import without starting a server; preserve the old profile archive and refuse a silent empty-library transition. Then make the final launcher bundle-local by default, package worker libs/helpers/Java/fonts/UI without the web JAR, use coherent 3.2.6 metadata, and test a data-preserving per-user upgrade. None of these installation/migration actions occurred in this batch. Firefox UI remains blocked by the earlier computer-tool policy and was not retried.

Final scoped frontend gate passed 47 tests across desktop worker/runtime boundary, password/session handling and optional OCR controls, together with typecheck, lint/theme/icons/CSS and formatting. The final worker golden rerun passed against the current 16,556,318-byte distribution. The caption focus token was corrected to an existing semantic token when the current theme gate identified its undefined predecessor.
