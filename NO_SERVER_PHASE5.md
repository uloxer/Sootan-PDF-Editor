# Standalone local security compatibility — phase 5

Verified 28 October 2026. This checkpoint does not install a replacement, migrate real profiles, publish or push. Installed 3.2.5 and its real Data/profile remain untouched.

## Connected local modes

- `add-password` → `password-protect`: explicit legacy 40-bit RC4, AES-128 and AES-256; new protection, permission changes preserving existing credentials/revision, and owner replacement when the retained opening credential is supplied. The existing UI default remains 128 bits; the worker/backend omitted-option default remains 256. The old `aes-encrypt` protocol ID remains accepted for compatibility; it is not a claim that 40-bit encryption is AES. New 128-bit worker protection uses AES rather than the legacy controller's default RC4-128 branch.
- `remove-password` → `decrypt`: credentials authenticate independently from selections; selective opening/owner removal, retained opening password, or explicit `removeAll`. Owner authentication is enforced offline and signed inputs cannot be rewritten by password tools. Removing an opening password while retaining restrictions retains protection, rather than silently granting unrestricted access.
- `cert-sign` → `cert-sign-pkcs12`: local PKCS12/PFX invisible or visible signature, reason/location/name, one-based page selection and bundled logo option. Shared retained appearance is 200×50 PDF points; CropBox origin/page rotation are retained, invalid page/undersized bounds fail. Expired or unsuitable signing-key usage fails. The old `cert-sign-invisible` protocol ID remains accepted. PEM/JKS/device signing remain explicitly unconnected; remote/server signing and TSA/network modes remain disabled.
- `validate-signature` → `signature-integrity`: CMS validity, coverage, current certificate validity, identity/dates/algorithm/key size/key usage, and offline chain/trust results. Only embedded intermediates, local JVM trust roots and an explicitly selected trust certificate participate. Embedded self-signed roots are not implicitly trusted. PKIX validation disables revocation; no AIA/OCSP/CRL/remote trusted-list requests are made. Current-time validation is reported; trusted historical timestamp validation is not claimed. Multiple CMS signers inside one PDF signature are explicitly unsupported rather than reporting trust for only one signer.
- `remove-cert-sign` → `signature-remove`: deliberate signature-field appearance flattening into a new unsigned output; the original remains unchanged. Other mutation paths still reject signed inputs.

`PdfPasswordRoles` and `PdfPermissionSecurityHandler` moved to the plain shared module; existing core facades delegate. The selective controller uses the shared mutation and preserves its server-policy/error-status adaptation. `PdfVisibleSignature` is shared with the existing certificate controller, and signature removal shares its PDFBox primitive. The worker retains its private read-only job copies, bounded JSON, strict allowlists and owned-process cleanup. Selected custom trust is a separate read-only grant capped at one MiB in frontend/native/Java; no filesystem root is exposed.

## Password inspection contract

The actual interactive UI already authenticates and inspects passwords in bundled `pdfAccessWorker`/PDFium through `pdfAccessService`; its session contract includes password/opening role, encrypted/signed flags, owner authentication, permission flags, revision and page count. These checks do not fetch a backend endpoint. This batch did not invent an unused password-check API or advertise partial Get ALL Info/Analysis JSON reports. Those server report contracts remain pending separately. Credentials remain session-only.

## Remaining work

Local PEM/JKS and device modes need bounded adapters and acceptance; online revocation/TSA/server signing are intentionally excluded by privacy scope. Full PDF inspection reports remain pending, although interactive local access checks already work. Page decoration/layout, attachments/portfolios, extraction/conversion, redaction/text editing and remaining form authoring/export retain their phase4 migration queue. Existing controllers/source are retained; this is not full installed parity or a finished no-server package. Final nonserver launcher/package, explicit old-origin library/profile migration and safe installed upgrade remain pending. Firefox UI remains policy-blocked and was not attempted; Firefox static worker adaptation remains separate. Unsigned/local-use redistribution caveats remain unchanged.
